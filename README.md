# sim-engine

A deterministic, flow-economy RTS in Rust, set in a civil war between the two halves of a colony garrison (GAME_SPECIFICATION.md §1.1). This is the vertical slice: one 10 km skirmish against a scripted AI, on an engine tested to 5,000 units and 2,000 physical shells at 10 ticks per second on an 81 km map.

- [`SPECIFICATION.md`](SPECIFICATION.md): the engine design and its acceptance gates
- [`GAME_SPECIFICATION.md`](GAME_SPECIFICATION.md): the game design, with the slice's scope in §18
- [`BALANCE.md`](BALANCE.md): how the game's numbers are made, from [`data/balance_targets.toml`](data/balance_targets.toml)
- [`data/units.toml`](data/units.toml): unit and structure stats, which are starting values for tuning

## Play

```bash
cargo run --release              # A skirmish against the AI, which plays easy (--ai normal for the full AI)
cargo run --release -- --fog off # The same with no fog of war: everyone, the AI included, sees the whole map
cargo run --release -- --battle  # The 5,000-unit stress test
cargo run --release -- --map scattered_isles  # A map that comes with the game: highland, twin_passes, saddleback, stillwater, or scattered_isles
cargo run --release -- --generate central_lake --map-size 10 --map-seed 7  # A map made from settings: passes, central_lake, or islands (--help lists the settings)
cargo run --release -- --map playtest  # A sandbox: 5 of every unit, no commander to lose, against two coastal bases a turtling AI holds
cargo run --release -- --scenario t3_siege  # A playtest scenario: a balance fight to play by hand (data/scenarios.toml)
```

Or play in the browser at **https://codymorterud.com/sim-engine/**, in any browser with WebGL2. The page asks for a map, the AI's difficulty and strategy, whether to play with fog of war, and optionally a seed, with a picture of each map (drawn by `examples/map_picture.rs` into `assets/web/maps`). Buttons show a portrait of each unit, drawn by `examples/portrait_sheet.rs` into `assets/portraits.png`: run `cargo run --release --example portrait_sheet` again after changing a model. Link previews and the web landing page use the social preview and thumbnail drawn by `examples/generate_social_assets.rs` into `assets/web/`. Its choices go in the address, so a game can be linked to directly: `?map=highland`, `?map=twin_passes`, `?map=saddleback`, `?map=stillwater`, `?map=scattered_isles`, or `?map=skirmish` for the maps, `?map=generate&kind=islands&size=10` (with `players`, `resources`, `reclaim`, `terrain`, `water`, and `mapseed` beside it; `--generate islands --map-size 10` on the command line) for a map made from settings, `?seed=7` for another seed, `?ai=normal` for a harder opponent, `?strategy=rush` (or `tech`, `air`, `naval`, `turtle`, or `random`; `--strategy` on the command line) for what it plays, `?teams=2v2` (`--teams 2v2`) for a 2v2 with an AI ally on Saddleback, Stillwater, or Scattered Isles, `3v3` on Saddleback, or `4v4` on Scattered Isles (the page offers only the matches the map chosen has starts for), `?map=playtest` for the playtest sandbox, `?fog=off` for no fog of war, `?battle` for the stress test, `?units` for the unit database: every unit and structure with all its numbers, by kind and tech level, which the game writes itself from the blueprints it plays with (`src/unit_database.rs`), so it can never disagree with them; or `?scenarios` for the playtest scenarios (below). `cargo run --release --example unit_database -- <folder>` writes the same page to a folder, to look at without building for the browser, and `--example scenario_page` the scenarios page. Without any of these, the page shows the choices and the game waits; with choices that cannot make a match, such as a map that does not exist, it says why in place of its loading line. It is rebuilt and published once a push to `main` passes CI and the soak (`.github/workflows/pages.yml`), and CI checks that the browser build compiles. The browser build is the same game, with sound through Web Audio, which browsers start only once you click or press a key in the game; it cannot load maps from your files, and is slower, so huge battles may stutter. To build it yourself:

```bash
rustup target add wasm32-unknown-unknown
cargo install trunk --locked
trunk serve --release    # then open http://127.0.0.1:8080
```

Destroy the enemy commander to win. Yours explodes if it dies, and your whole team goes with it.

1. Tap Space to select your commander. Choose a structure from the bottom panel, then left-click the ground to place it.
2. Materiel extractors go on the teal deposits, and snap to the nearest free one near the cursor. Power generators supply energy. Land factories build units.
3. Click a factory to queue units. Every build menu is one bar: pick T1, T2, or T3 at its left to see that level's items, and hover over an item for its cost and what it does. Factories build in the open: you can watch each unit take shape in the bay, then drive out of the end facing the rally point (aircraft lift off their pad). Right-click the ground with a factory selected to set its rally point. With several factories selected, every order goes to all of them that can follow it. A factory still under construction takes orders too, and starts on them once it is built. Once an upgrade is queued, the factory can also queue what the upgrade unlocks, which waits for it to finish.
4. If a row of the economy panel at the top left glows red and says Stalled, you are spending faster than you earn, and everything slows down.

Selected units show a dashed trail through their pending orders, in the order they will carry them out, and selected factories show a dimmer line to their rally point. Queued builds always show a dimmed footprint, and a faint grid appears while placing, so that the next one can be lined up against them. Units that destroy enemies earn their materiel as experience, shared by the damage each did, and rise through five veteran ranks, shown as gold pips: each adds 10% health, heals at once, and adds regeneration. Weapons swivel at their own rate and only fire once they point at their target, so a tank's turret has to come round first. Units only move forward along the way they face. Vehicles turn like cars, in arcs no tighter than their turn radius, while walkers such as the commander and bots turn on the spot. The commander's legs and the engineer's hull face the way they move, while the body or arm above turns to face what they are working on, and a beam with moving pulses joins them to it for as long as work is really happening: it stops if they are out of resources. Each option in the command panel shows its key, including the unit orders above, which are also buttons, and the panel lists what is selected has queued: right-click an item to remove it. A site that was already started stays, and can be finished by assisting it. The bar on the right selects your commander or factories without moving the view: click a tier for the factory closest to your view, double-click for all of them, and hold Shift to add to the selection. Zoomed in, you hear what you see, in stereo: the sea where water is in view, ships under way, land units moving, aircraft passing, and the soft laser shimmer of builders' beams and, lower, of factories at work. Selecting units gives a short, soft blip, and an alarm and an alert show when your commander takes damage, at most once every 30 seconds. Run with `--sound-check` to hear each sound, or `cargo run --release --example sound_preview -- <folder>` to write each to a WAV file. The panel shows what a selected structure makes and what a factory is really spending. Trees give quick energy and a little materiel when reclaimed, and rocks give materiel. Building over them clears them, and you get what they held. Debris can be shot to pieces: every shell that lands on it, and every blast that reaches it, wears it down, and it loses its materiel as it goes, so a graveyard you cannot hold can be denied to the enemy. Trees and rocks are not harmed. A Shield Generator raises a see-through dome that stops enemy shells from outside while your units under it fire out. It heals over time, collapses for 30 seconds when worn out, costs energy while up (less beside power generators), and falls if your energy runs out. Splash that strikes overlapping domes hits them all. Pause it with O to save energy. Missile launchers build their own missiles with Q and fire them only when ordered: right-click an enemy, or attack the ground. A Tactical Missile Launcher keeps up to 6 cruise missiles and fires them over walls and hills at its target until it is gone, and a Tactical Missile Defense shoots them down one at a time. A Strategic Missile Launcher keeps up to 5 nuclear missiles and fires one for each order, anywhere on the map: its inner ring destroys anything, and its outer ring only light units and buildings. Shields do not stop them, but a Strategic Missile Defense with an interceptor built shoots down any that flies within its range. A Radar shows enemies out of sight as blips, and upgrades with U to a T2 Radar and then a Deep Scan Array, which sees through stealth, cloaks, and decoys. A Stealth Field Generator hides your units near it from enemy radar and shows the enemy decoy blips. Your commander has a little deep scan of its own. Its enhancements, under the Enhance tab of the command bar, fit in three slots: a heavier cannon in the weapons bay; the T2 and T3 fabrication packs, which it needs to build higher-tier structures, or a repair system in the left; and a shield, stealth and then a cloak, a teleporter, or a resource generator on the back. It stands still while one is built, and a new order cancels it. Once the T2 or T3 fabrication pack is started, that tier's structures can already be ordered: they wait behind the suite, and are dropped if it is cancelled. Anything upgrading, yours or an enemy's in sight, has a pulsing purple ring, and yours also show a progress bar. Your factories, missile silos, and strategic missile submarines show a blue bar for how far along the current unit or missile is, only while they are making one (not with a full silo). A Rig Yard builds field rigs: heavily armored engineers with a strong gun and income of their own, whose deaths do not end the match, with enhancements of their own. Selecting units, one or a group, rings every range they reach on the ground, each kind in its own color and merged into one outline around the group: ground fire, anti-air (anything that can fire at aircraft), torpedoes, artillery's too-close edge, shields, missile and torpedo defense, radar, sonar, deep scan, and stealth fields. The ranges button at the top opens a list of those kinds; each one ticked is outlined thinly for all your finished units, selected or not, at any zoom. Radar and sonar are ticked to begin with. Zoomed out, deposits and vents are marked, and moving units show when they will arrive. To fire at a blip, attack the ground there. An order that cannot be reached, because walls or buildings cut it off, is cancelled with a message, and units move on to whatever else they were told to do. A marker and a line of text confirm each order. A click that shows nothing never reached the game. The window title shows the frame rate and tick time. Run with `--help` for the headless and test modes. An Air Factory builds aircraft, which fly over walls, water, and cliffs and land when they have nothing to do, where there is open ground, or circle where there is none. Landed, they can be hit by ground units but not by anti-air: the Air Scout sees and has radar far around it, the Interceptor shoots down aircraft and nothing else, and the Attack Bomber makes passes over ground targets, dropping a bomb on each, and keeps to the target it picks until it is destroyed, even on an attack-move. Every unit on an attack-move or a patrol does the same: once it picks a target, it chases it until it is destroyed, then goes on with its move. The Air Factory upgrades to T2 for the Gunship, which hovers over what it attacks, and the Fighter-Bomber, which carpets the ground with napalm and fights aircraft, and to T3 for the Spy Plane, Air Superiority Fighter, Strategic Bomber (one small nuclear bomb at a time, and guns against aircraft on its tail), and Heavy Gunship. Flak (and Mobile Flak) fires slow shells that burst where an aircraft is headed and hit every one nearby: it shreds gunships and slow aircraft, but fast T3 aircraft mostly outfly it, and shrug off T1 anti-air. The T3 SAM Launcher, and the cruiser at sea, bring them down. Artillery installations (T2 and T3) and Mobile Heavy Artillery shell targets from long range, but cannot hit anything too close, and their shells scatter a little. An installation's shots cost energy, and power generators beside it make them cheaper and faster. A Naval Factory, built on deep water near the shore, upgrades to T2 and T3 for Destroyers, Cruisers, which fire cruise missiles on their own and shoot down missiles, Battleships, and Battlecruisers, and builds Frigates, which sail only where the water is deep enough and shell the shore and aircraft alike. The Escort Corvette carries a dome over your fleet and shoots down torpedoes, as destroyers and battlecruisers do. Right-click a missile's build button to build them one after another, and again to stop. The Strategic Missile Submarine builds nuclear missiles on order and fires cruise missiles on its own, and the Mobile Missile Launcher fires cruise missiles on its own at anything in range. Your commander walks along the seabed, hidden and unable to fire while under the water, and the Assault Hovercraft hovers over land and water alike, as engineers do, so they can build out on the water. Attack Submarines sail submerged, where only torpedoes reach them and only Sonar finds them; Torpedo Launchers and Torpedo Bombers hunt them and ships. Aircraft burn fuel in the air, and without it fly low and slow. An Airfield (T2) refuels and repairs four aircraft at a time: right-click it with aircraft selected. Aircraft on patrol stay in the air, and go to refuel on their own when low. Only anti-air can hit aircraft in flight: interceptors, the Anti-Air Turret, and Mobile Anti-Air from the land factory. Two maps come with the game: `--map highland`, a 10 km plateau of hills, outcrops and rock fields, and `--map twin_passes`, 20 km with a sea down the middle crossed by two land bridges.

**Playtest scenarios.** The fights the balance harness measures, to play by hand: T3 artillery sieging a shielded T3 position and defending against massed T1, Heavy Walkers screening artillery, raiders against artillery, the T1 line mirror, the T2 skirmisher against the line, bombers against a line with and without anti-air, and the fights between domains in `[domains]` (2026-11-24): fleets against air forces and overwhelming torpedo bombers at T2 and T3, submarines, hovercraft, ships against coasts and torpedo launchers, and T2 air against a land army, each naming the balance target it plays. Each is on flat open ground, open sea, or a shore; you play Blue with only the units listed, and Red's units attack at once or hold their ground. A bar shows each side's share of its materiel left, weighted by health, as the harness scores a fight (Red's is hidden while fog of war is on). They are in `data/scenarios.toml`, which the game builds them from (`src/sim/playtest_scenarios.rs`), and from which it writes the page that lists them, with each side's units and their numbers from the unit data (`src/scenario_page.rs`): `?scenarios` in the browser, linked from the landing page, with links to play each with or without fog of war (`?scenario=t3_siege&fog=off`), or `--scenario <id>` on the desktop.

## Validate

See [`SPECIFICATION.md` §7](SPECIFICATION.md#7-how-to-validate-the-build) for the full list.

```bash
cargo test --release
cargo test                                # Unoptimized, so that arithmetic overflow fails loudly
cargo clippy --all-targets -- -D warnings # Enforces the determinism rules
cargo test --release --target x86_64-apple-darwin --test determinism_test
cargo bench
cargo run --release -- --soak 100         # Plays and replays 100 AI-vs-AI matches
cargo run --release -- --autotest 60 --fast-forward 10000   # Opens a window for 60 seconds
```

Every push to `main` runs most of these on GitHub's runners too. CI (`.github/workflows/ci.yml`) runs both test suites, clippy on every target and for the browser, the golden checksums again on 64-bit ARM, as Apple silicon is, and the check that other games' names stay in PROVENANCE.md. Autotest (`.github/workflows/autotest.yml`) plays the fast-forwarded match and the 5,000-unit battle in a window, drawn in software under a virtual display, and checks that each starts, plays, and ends with its checksum; its frame times say nothing about speed. The benchmarks stay local, as their timing limits would fail falsely on a shared runner.

Every push to `main` also runs the soak on GitHub's runners (`.github/workflows/soak.yml`): the 200 skirmish matches, 120 on each of the five bundled maps, 60 2v2s on each of the three with team starts, 60 3v3s on Saddleback, and 20 4v4s on Scattered Isles, in shards of 25 seeds, one runner each, all from one release build. The run's summary page adds up wins by side, unfinished matches, and replay mismatches per map, with the chance of a split at least that lopsided between equally strong sides (a p below 0.05 suggests a real lean). Tick times are reported there but do not fail the run (`--no-tick-gate`), since a shared runner's other load would fail it falsely; the benchmarks check speed locally. The strategy soak (`.github/workflows/strategy-soak.yml`), started by hand with `gh workflow run strategy-soak.yml`, plays every AI strategy against every other on every map, 50 matches a pair a map by default (2,000 in all over the four maps), half each way round, and reports each matchup and each strategy's share of what it decided against the 55% limit of `[strategy]` (`--soak` takes `--strategies blue,red` for this). Each pull request into `main` gets CI and a smaller soak (40 skirmish matches, 20 on each bundled map, 10 of each team match, and 5 4v4s, in shards of 10): enough to catch a match that never ends, a replay that differs, or a panic, but not to judge a side's lean, which the full soak does once the pull request is merged. Start a soak by hand from the Actions tab, or with `gh workflow run soak.yml`; its inputs set the matches per map and per runner, for example `gh workflow run soak.yml -f bundled_matches=500` for a closer look at a map's fairness, with `-f maps=twin_passes` to play only that map and `-f first_seed=121` to play seeds the push's soak did not.

Any soak match can be watched: the simulation and the AIs are deterministic, so the map and seed alone replay it. `cargo run --release -- --watch --map highland --seed 223` shows everything, with both teams' economies; `--view blue` or `--view red` starts in one side's sight instead. In the match, V steps between everything, Blue, and Red, - and = change the speed up to 16x, and A tap of Space pauses; held, with the mouse, it turns the camera. In the browser, use the page's Watch section, or `?watch&map=highland&seed=223&view=all`.

**Coverage.** Every push to `main` also measures how much of the code the tests run (`.github/workflows/coverage.yml`), with [cargo-llvm-cov](https://github.com/taiki-e/cargo-llvm-cov): the release test suite, instrumented. The run's summary page has line coverage by area (simulation, AI, balance and soak, rendering and interface, everything else) and by file, and its `coverage-report` artifact is the whole report as HTML, line by line, with what ran and what did not. It measures only: it fails no build, and the website does not wait for it. Locally, after `cargo install cargo-llvm-cov` and `rustup component add llvm-tools-preview`, `cargo llvm-cov --release --open` runs the tests and opens the report.

The stored checksums in `tests/golden/` change whenever simulation behavior changes on purpose. Update them with `UPDATE_GOLDEN=1 cargo test --release --test determinism_test`, then confirm that the x86-64 run still matches.
